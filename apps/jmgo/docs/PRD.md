# 产品需求文档（PRD）— 坚果 N1S 4K 兼容版 TVBox 客户端

> 版本 v1.2（2026-11-08，基线变更同步）
> 上位契约：`apps/jmgo/SPEC.md` v0.1
> 基线变更：源码编译路线证伪（52 个私有 media3 类未开源、作者私有 AAR 未入库），改为「官方产物聚合 + 兼容性验证」；详见 `docs/ACCEPTANCE.md` 第 6 节。

## 1. 背景与问题

用户使用坚果 N1S 4K 高亮版（国行 J31-8K2 / Android 11 / MT9667 / 3GB RAM / 64GB ROM，
坚果定制系统，无 Root、无网口）看影视。已试过 OK 影视（FongMi/Release 官方包）与 tvbox.clbug.com 官网版，均闪退；
现用「蜂蜜的 v7 版本」（40MB 以上、包名 `com.fongmi.android.tv`、官方 FongMi 5.8.7 系）勉强能用，但**用一会儿随机闪退**。

根因尚未在实机取证，最可疑的三类叠加：3GB RAM 下的生命周期/资源释放缺陷、独立 runtime 模块对 GitHub 的可达性依赖、
以及 32/64 位主包与 runtime 模块的潜在不匹配。

## 2. 目标与用户

- **目标**：为这台机器聚合官方 `FongMi/Release` 5.8.7 的 4 个已编译包，经机械校验与兼容性验证后发布可覆盖安装的 APK，并通过实机对照试装定位「用一会儿随机闪退」的死因类别。**不承诺修好闪退，只承诺可诊断、可对照、可归因。**
- **用户**：本机主，非开发者；交付物是「能下载、能装上、能用」的 APK 与一份可照做的取证手册，不是源码或说明书。

## 3. 功能需求（MVP）

| 编号 | 需求 | 优先级 | 验收摘要 |
| --- | --- | --- | --- |
| F1 | 四包聚合与架构对照 | P0 | 聚合官方 `FongMi/Release` 5.8.7 的 4 个包（leanback / mobile × `arm64_v8a` / `armeabi_v7a`），逐个机械校验签名指纹 / ABI / 包名 / versionName |
| F2 | 实机稳定性对照与归因 | P1 | 按 `docs/FIELD-TEST.md` 做四包对照试装、全量日志与内存曲线取证，定位死因类别；不对官方包做源码裁剪，不做「加 largeHeap」 |
| F3 | push 即聚合发布可安装 APK | P0 | Actions 成功 → Artifact + Release，附 sha256 / run id / commit / flavor / ABI / `upstream-verify.json` |
| F4 | 官方原签名可覆盖安装 | P0 | 沿用官方原签名，与用户现装官方 5.8.7 32 位包同签名，覆盖安装不丢收藏 / 历史 / 播放进度 |

## 4. 明确不做

新 UI / 内置配置源 / 直播弹幕 / DLNA / 网盘登录 / 投屏 / 多机型矩阵 / Root 刷机 /
账号体系 / 应用内热更新 / 清数据或后台白名单绕过 / 引入 `ApplicationExitInfo`（API 31+，本机 API 30 不可用）。

## 5. 关键约束

- 四包聚合（2 flavor × 2 ABI），实机对照试装决定推荐；不靠「芯片 64 位」锁单变体，也不预设任一包为正确方向。
- runtime 模块离线可用，拉取失败给错误态不闪退。
- 沿用官方原签名，与用户现装包一致，否则无法覆盖安装；禁止为换绿改签名。
- 不向用户索取私密配置 URL / APK 文件名 / 系统 getprop；留出集用仓库已公开配置地址。
- 不承诺修好闪退；交付价值是「可诊断、可对照、可归因」。

## 6. 成功标准

连续播放 60 分钟不闪退（P0 门槛）、切换线路 ≥20 次跨 ≥3 站点、前后台切换 ≥10 次、
TOTAL PSS ≤512MB、内存 60 分钟净增长 ≤50MB 且 GC 后回落、首次导入配置 30 秒内有结果。
完整阈值见 `docs/ACCEPTANCE.md`（AC-01~AC-31；四包对照试装见顺延 AC-32）。**阈值一字未降。**
